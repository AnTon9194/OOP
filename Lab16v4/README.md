# Звіт з лабораторної роботи №10
**Тема:** LINQ в дії: фільтри, join, агрегації. Продуктивність.  
**Варіант:** 4 (Сценарій: Бібліотека)

## 1. Аналіз продуктивності LINQ-запитів
Під час виконання лабораторної роботи було проведено заміри часу для чотирьох типів запитів у двох різних синтаксисах за допомогою `System.Diagnostics.Stopwatch`.

### Основні висновки:
1. **Еквівалентність синтаксисів:** Швидкість виконання запитів за допомогою *Синтаксису методів (Method Syntax)* та *Синтаксису запитів (Query Syntax)* є абсолютно однаковою. Невеликі відхилення в тіках (`ticks`) викликані виключно станом операційної системи, планувальником процесора та JIT-компіляцією під час першого проходу. Компілятор C# завжди транслює синтаксис запитів у виклики відповідних методів розширення LINQ перед генерацією IL-коду.
2. **Накладні витрати складних операцій:** Операції `Join` (Запит 2) та `GroupBy` (Запит 3) потребують побудови внутрішніх індексів (хеш-таблиць) у пам'яті для ефективного зіставлення елементів колекцій. На малих колекціях (10-20 елементів) різниця непомітна, але на великих масивах даних ці операції суттєво відрізнятимуться за часом від простої лінійної фільтрації `Where`.
3. **Ефект відкладеного виконання:** Вимірювання фіксувало час разом із викликом `.ToList()`. Це примусово матеріалізувало запит у пам'яті. Без цього виклику час формування запиту дорівнював би майже нулю, оскільки виконання відкладається до моменту ітерації (наприклад, у циклі `foreach`).

## 2. Відповіді на контрольні питання

### 1. Поясніть різницю між синтаксисом запитів та синтаксисом методів у LINQ. Коли який краще використовувати?
* **Синтаксис запитів (Query Syntax):** Схожий на декларативний SQL (`from ... in ... where ... select`). Він зручніший та читабельніший для складних запитів, що містять декілька об'єднань (`join`), групувань (`group by`) або підзапитів.
* **Синтаксис методів (Method Syntax):** Використовує лямбда-вирази та ланцюжки методів розширення (`.Where().Select()`). Він є більш гнучким, підтримує абсолютно всі оператори LINQ (деякі з них, наприклад `.Take()`, `.Skip()`, `.Distinct()`, відсутні у синтаксисі запитів) та частіше використовується на практиці для простих лінійних операцій.

### 2. Для чого використовуються операції Join та GroupJoin? У чому їхня відмінність?
* **Join:** Використовується для внутрішнього об'єднання (аналог `INNER JOIN` в SQL). Поєднує два джерела даних на основі збігу ключів та повертає плоский результат (один елемент зліва + один справа). Якщо відповідності немає, дані відкидаються.
* **GroupJoin:** Створює ієрархічне об'єднання (аналог `LEFT OUTER JOIN`). Для кожного елемента першої колекції він формує цілу *групу (колекцію)* пов'язаних елементів з другої колекції. Навіть якщо для лівого елемента немає пари, він все одно залишиться в результаті з порожнім списком дочірніх елементів.

### 3. Наведіть приклади агрегуючих операцій LINQ та поясніть їхнє призначення.
Агрегуючі операції обробляють набір значень та зводять їх до одного результату:
* `Count()` — рахує загальну кількість елементів у вибірці.
* `Sum()` — обчислює арифметичну суму числових значень (наприклад, сума цін товарів).
* `Average()` — знаходить середнє арифметичне значення.
* `Min()` / `Max()` — визначають мінімальний та максимальний елементи відповідно.
* `Aggregate()` — виконує кастомну покрокову акумуляцію значень за допомогою заданої функції.

### 4. Як можна виміряти продуктивність LINQ-запитів? Які фактори впливають на неї?
Продуктивність вимірюється класом `System.Diagnostics.Stopwatch`, або спеціалізованими інструментами на кшталт **BenchmarkDotNet** для мікро-бенчмаркінгу.

**Фактори, що впливають на неї:**
1. **Матеріалізація запиту:** Виклик `ToList()`, `ToArray()` або `Count()` примусово запускає виконання всього ланцюжка обчислень.
2. **Тип джерела (LINQ to Objects vs LINQ to Entities):** Робота з колекціями в RAM відбувається швидко, тоді як робота з БД через Entity Framework залежить від якості трансляції LINQ у SQL та швидкості мережі.
3. **Алгоритмічна складність операцій:** Сортування (`OrderBy`) та групування (`GroupBy`) копіюють дані та вимагають більше CPU і пам'яті, ніж проста фільтрація.
4. **Зайві ітерації:** Неправильне проєктування, що призводить до багаторазового перебору однієї й тієї ж колекції (наприклад, викликати `.Count()` а потім `.First()` замість одного проходу).
