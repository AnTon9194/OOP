# IndependentWork2 — Самостійна робота №2

## Контрольні запитання та відповіді

### 1. Навіщо потрібне перевантаження конструкторів у класі `Product`?
Перевантаження конструкторів дозволяє створювати об'єкти класу `Product` у різних сценаріях з різним рівнем наявної інформації. Наприклад:
- Коли відомі всі атрибути товару (назва, ціна, категорія, кількість на складі), використовується основний конструктор.
- Коли при швидкому додаванні товару відомі лише назва та ціна, використовується скорочений конструктор із дефолтними значеннями ("Uncategorized", 0).
- Коли потрібно продублювати існуючий товар, використовується конструктор копіювання.
Це робить API класу гнучким, зручним та зрозумілим при використанні.

### 2. Чому конструктор копіювання зручно реалізовувати через `: this(...)`?
Виклики `: this(...)` (делегування / переадресація конструкторів) дозволяють уникнути дублювання коду ініціалізації (принцип DRY — Don't Repeat Yourself). Усі перевірки, присвоєння полів та логіка ініціалізації зосереджені в одному основному конструкторі. Допоміжні конструктори лише передають необхідні параметри в основний.

### 3. Які переваги дає read-only доступ до властивостей після створення об'єкта?
Read-only властивості (із гетером `{ get; }` або виразом `=>`) забезпечують **незмінність (immutability)** та **інкапсуляцію** об'єкта після його створення. Це запобігає випадковій або некоректній зміні критичних даних (наприклад, ID, ціни чи назви) ззовні класу, робить поведінку програми більш передбачуваною та безпечною.

### 4. У яких випадках перевизначення `ToString()` спрощує налагодження та демонстрацію роботи класу?
Перевизначення `ToString()` дозволяє отримати зрозуміле, форматоване текстове представлення об'єкта за замовчуванням (наприклад, при передачі об'єкта у `Console.WriteLine(product)` або під час перегляду змінних у відлагоджувачі (debugger)). Без перевизначення `ToString()` повертав би лише назву типу (`IndependentWork2.Product`), що не надає жодної інформації про поточний стан об'єкта.
