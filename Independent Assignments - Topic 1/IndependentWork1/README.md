# Самостійна робота №1: Базовий синтаксис C# і оголошення класів

##  Структура проєкту

* `Rectangle.cs` — клас геометричної фігури "Прямокутник" (містить приватні поля `_width`, `_height`, властивості `Width`, `Height`, read-only властивість `Area`, метод `CalculatePerimeter()` та `PrintInfo()`).
* `BankAccount.cs` — клас банківського рахунку (містить приватні поля `_accountNumber`, `_balance`, read-only властивість `AccountNumber`, метод з логікою `Deposit()` та `Withdraw()`).
* `Employee.cs` — клас співробітника (містить приватні поля `_fullName`, `_monthlySalary`, властивості, read-only властивість `AnnualSalary`, метод `CalculateBonus()`).
* `Program.cs` — головна точка входу з демонстрацією роботи екземплярів усіх створених класів.


##  Контрольні запитання та відповіді

### 1. Які мінімальні елементи повинен містити клас у цьому завданні?
**Відповідь:**
Відповідно до вимог завдання, кожен клас повинен містити:
* Щонайменше **2 приватні поля** (наприклад, `_width`, `_height` або `_accountNumber`, `_balance`);
* Щонайменше **1 публічну властивість** з геттером і сеттером (`get` / `set`) або read-only властивість для безпечного доступу до поля;
* Щонайменше **1 метод**, що реалізує обчислювальну логіку або перевірку стану об'єкта (наприклад, `CalculatePerimeter()`, `Withdraw()`, `CalculateBonus()`);
* **Конструктор з параметрами** для ініціалізації полів об'єкта під час його створення.

---

### 2. Чому поля доцільно робити приватними, а доступ до них надавати через властивості?
**Відповідь:**
Це є основою принципу **іннкапсуляції** (приховування внутрішнього стану об'єкта):
* **Захист даних та валідація:** Приватні поля (`private`) захищені від прямої та неконтрольованої зміни іззовні. Через властивості (`properties`) ми можемо додати перевірку коректності значень (наприклад, заборонити від'ємну ширину чи від'ємну зарплату).
* **Гнучкість та керування доступом:** Властивості дозволяють тонко налаштовувати рівні доступу — робити поля доступними лише для читання (`get;` без `set;` або з `private set;`), обчислювати значення "на льоту" (обчислювальні властивості, як `Area` чи `AnnualSalary`) без збереження зайвих даних у пам'яті.

---

### 3. Для чого в класі потрібен конструктор і як він пов'язаний зі станом об'єкта?
**Відповідь:**
* **Призначення конструктора:** Конструктор — це спеціальний метод класу, який викликається автоматично під час створення нового екземпляра об'єкта (через оператор `new`). Його головна мета — коректно ініціалізувати початковий стан об'єкта (призначити початкові значення його полям).
* **Зв'язок зі станом:** Стан об'єкта визначається сукупністю значень його полів у конкретний момент часу. Передаючи параметри в конструктор, ми гарантуємо, що об'єкт відразу після створення перебуватиме в коректному, цілісному та працездатному стані (наприклад, банківський рахунок одразу матиме номер і початковий баланс, а прямокутник — коректні геометричні розміри).

---

### 4. Як у Main показати, що методи класу працюють коректно?
**Відповідь:**
У методі `Main` для кожного класу необхідно:
1. Створити екземпляр класу через оператор `new`, передавши початкові дані в конструктор.
2. викликати його методи з різними параметрами (включаючи граничні випадки, наприклад, спробу зняти суму, яка перевищує баланс).
3. Вивести результати виконання методів та поточний стан властивостей у консоль (за допомогою `Console.WriteLine`), щоб наочно продемонструвати зміну стану об'єкта чи правильність математичних обчислень.
