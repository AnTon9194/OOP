# Самостійна робота №6: Приклади поліморфізму в .NET

##  Опис проєкту

Проєкт демонструє практичне використання та переваги механізму поліморфізму в платформі .NET на прикладі трьох ключових паттернів:
1. **Поліморфізм через базовий клас `System.Object`** (перевизначення віртуального методу `ToString()`).
2. **Поліморфізм через інтерфейси (`IEnumerable<T>`)** (створення власної колекції `MyCustomCollection`).
3. **Поліморфізм через абстрактні класи (`System.IO.Stream`)** (єдиний метод `ProcessStream` для `FileStream` та `MemoryStream`).



##  Структура проєкту

* `Program.cs` — головна точка входу з демонстрацією всіх трьох сценаріїв.
* `Product.cs`, `Customer.cs`, `Order.cs` — прикладні класи з перевизначеним методом `ToString()`.
* `MyCustomCollection.cs` — клас колекції, який реалізує `IEnumerable<string>`.
* `StreamProcessor.cs` — клас із поліморфним методом `ProcessStream(Stream stream)`.


##  Звіт за результатами дослідження

### 1. Поліморфізм через `System.Object`
* **Як проявляється:** Усі типи C# (як значущі, так і посилання) успадковуються від `System.Object`. Клас `Object` містить віртуальні методи, зокрема `ToString()`.
* **Приклад з коду:**
  ```csharp
  List<object> objectsList = new List<object> { product, customer, order };
  foreach (object obj in objectsList)
  {
      Console.WriteLine(obj.ToString()); // Динамічне зв'язування викличе перевантажену версію кожного класу
  }
  ```
* **Переваги:** Можливість зберігати різнотипні об'єкти у єдиній колекції та звертатися до базового функціоналу без явного приведення типів.

### 2. Поліморфізм через `IEnumerable<T>`
* **Як проявляється:** Цикл `foreach` працюватиме з будь-яким типом, що надає метод `GetEnumerator()`, зафіксований у `IEnumerable<T>`.
* **Приклад з коду:**
  ```csharp
  MyCustomCollection customCollection = new MyCustomCollection();
  foreach (string item in customCollection)
  {
      Console.WriteLine(item);
  }
  ```
* **Переваги:** Повне абстрагування від внутрішньої структури зберігання даних (масив, зв'язаний список, дерево тощо). Клієнтський код використовує уніфікований синтаксис.

### 3. Поліморфізм через абстрактний клас `Stream`
* **Як проявляється:** Абстрактний клас `Stream` визначає загальний контракт читання/запису. Конкретні реалізації (`FileStream`, `MemoryStream`, `NetworkStream`) реалізують специфічну логіку.
* **Приклад з коду:**
  ```csharp
  public static void ProcessStream(Stream stream)
  {
      // Єдина логіка для файлів, пам'яті, мережі
      byte[] buffer = new byte[1024];
      stream.Read(buffer, 0, buffer.Length);
  }
  ```
* **Переваги:** Повторне використання коду та гнучкість. Метод `ProcessStream` спроєктований так, що може обробляти будь-які майбутні типи потоків без модифікації свого коду.


##  Контрольні запитання та відповіді

### 1. Як поліморфізм проявляється при роботі з `List<object>`?
**Відповідь:**  
У `List<object>` можна додавати об'єкти будь-яких типів, оскільки в .NET усі класи неявно успадковані від `System.Object`. Коли ми ітеруємося по елементах такої колекції та викликаємо метод `ToString()`, завдяки механізму пізнього (динамічного) зв'язування викликається перевизначена (`override`) версія методу саме того конкретного типу, екземпляром якого є об'єкт у пам'яті, а не базова реалізація `System.Object.ToString()`.

### 2. Що потрібно реалізувати в `MyCustomCollection`, щоб її можна було перебирати через `foreach`?
**Відповідь:**  
Клас `MyCustomCollection` повинен реалізувати інтерфейс `IEnumerable<T>` (або неузагальнений `IEnumerable`). Для цього необхідно реалізувати:
1. Метод `IEnumerator<T> GetEnumerator()`, який повертає об'єкт-ітератор.
2. Неузагальнений метод `IEnumerator IEnumerable.GetEnumerator()`, який зазвичай просто викликає узагальнений варіант.  
Також у C# достатньо надати будь-який публічний метод `GetEnumerator()`, який повертає тип з методами `MoveNext()` та властивістю `Current` (шаблон Enumerator).

### 3. Чому метод `ProcessStream(Stream stream)` є прикладом поліморфної роботи з абстрактним класом?
**Відповідь:**  
Сигнатура методу приймає параметром базовий абстрактний клас `Stream`. Метод оперує високорівневими абстрактними понятиями (читання байтів, позиціонування), не знаючи конкретної реалізації. Під час виконання ми можемо передати як `FileStream`, так і `MemoryStream` (або `NetworkStream`), і для кожної конкретної сутності виконається її власна реалізація базових абстрактних методів (наприклад, читання з диска або читання з масиву байтів у RAM).

### 4. Які переваги дає єдиний інтерфейс роботи для різних типів потоків і колекцій?
**Відповідь:**  
* **Гнучкість та розширюваність:** Клієнтський код не залежить від конкретних класів. Додавання нового типу потоку чи колекції не вимагає переписування існуючої логіки.
* **Повторне використання коду:** Один і той самий алгоритм обробки (наприклад, архівація, шифрування, фільтрація) може працювати з різними джерелами даних.
* **Спрощення тестування (Mocks/Stubs):** Можна легко підмінити реальний файловий/мережевий потік на `MemoryStream` під час написання юніт-тестів.
