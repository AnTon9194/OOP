# Лабораторна робота №5: Поліморфізм

Варіант 4: Поліморфні пристрої (Device -> Printer, Scanner, Monitor).

## Опис структури
Device - базовий клас із полем Brand та віртуальним методом `PerformAction()`.
Printer, Scanner, Monitor - похідні класи, які перевизначають override метод для виконання специфічних дій.

## Контрольні запитання

1. Що таке поліморфізм і як він реалізується в C# за допомогою virtual та override?

 Поліморфізм - це принцип, що дозволяє взаємодіяти з різними об'єктами через спільний інтерфейс або базовий тип, отримуючи специфічну для кожного об'єкта поведінку. В C# базовий клас позначає метод як `virtual`, а класи-нащадки перевизначають його за допомогою `override`. CLR динамічно визначає точний тип об'єкта під час виконання та запускає потрібну реалізацію.

2. Поясніть поняття динамічного зв’язування. Чим воно відрізняється від статичного?

 Статичне зв'язування (раннє) відбувається на етапі компіляції - компілятор точно знає, який метод викликається (наприклад, звичайні методи, перевантажені методи). Динамічне зв'язування (пізнє) відбувається під час виконання програми: рішення про те, який саме метод викликати, приймається на основі реального типу об'єкта в пам'яті (застосовується для віртуальних методів та інтерфейсів).

3. Наведіть приклад, як поліморфізм дозволяє писати більш гнучкий та розширюваний код.

 Уявімо систему оплати. Ми створюємо базовий клас `PaymentProcessor` з віртуальним методом `Process()`. Потім створюємо нащадків: `CreditCardProcessor`, `PayPalProcessor`, `CryptoProcessor`. Основний код програми може приймати масив `PaymentProcessor[]` і в циклі викликати метод `Process()`. Якщо згодом з'явиться новий метод оплати, нам не доведеться змінювати основну логіку програми - достатньо буде просто додати новий клас.

4. Які переваги дає використання колекцій базових типів для роботи з поліморфними об’єктами?

 Це дозволяє зберігати різні об'єкти-нащадки в одній спільній структурі даних (наприклад, `List<Shape>`, де лежать і `Circle`, і `Rectangle`, і `Triangle`). Програма може обробляти всю колекцію в одному циклі, викликаючи спільні методи (наприклад, `Draw()`), що значно скорочує дублювання коду та робить архітектуру гнучкою.
